# 鞋库拍照匹配技术方案总结

## 1. 项目目标

本项目是一个部署在 GitHub Pages 的纯前端鞋款检索应用。样品数据提前从 Excel 导入当前设备的浏览器数据库；现场使用手机拍照或从相册选择图片，系统在本机返回最相似的 Top 5 样品编号。

线上地址：<https://tulipking888.github.io/shoe-match-web/>

系统没有业务服务器，样品照片和检索特征不会上传到远端。

## 2. V5 整体架构

```text
GitHub Pages 静态资源
        ↓
浏览器加载 ONNX Runtime Web + DINOv2-small INT8 模型
        ↓
Excel/单条样品图在本机提取特征
        ↓
IndexedDB 保存业务字段、缩略图和检索特征
        ↓
查询图在本机计算多视角特征并检索 Top 5
```

主要组件：

- HTML、CSS、原生 JavaScript：界面与业务流程；
- JSZip：解析 `.xlsx` 压缩包、工作表关系和内嵌图片；
- ONNX Runtime Web：在浏览器 WASM 环境运行模型；
- DINOv2-small INT8：生成全局语义和局部视觉特征；
- IndexedDB：保存样品、导入批次、缩略图和特征；
- Service Worker：缓存网页、运行库和模型，支持完成首次加载后的离线使用。

## 3. 入库特征

每张样品图只执行一次模型推理，并从同一次输出中生成三类特征：

### 3.1 全局鞋型特征

- 使用 DINOv2 的 CLS 向量；
- 维度为 384；
- 用于快速召回整体轮廓和鞋款语义接近的候选。

### 3.2 局部细节特征

- 将模型的 16×16 patch token 池化为 4×4，共 16 个局部区域；
- 每个区域仍为 384 维；
- 保存前量化为 Int8，单张图约增加 6 KB；
- 用于比较鞋底、拉链、网布、缝线和侧面饰条。

### 3.3 前景颜色特征

- 根据边缘区域估计背景颜色；
- 使用 Lab 色差、HSV 饱和度和亮度分离主要前景；
- 对前景生成色相、饱和度、亮度及 Lab 分布特征；
- 用于区分同鞋型的 black、l.blue、burgundy、taupe 等配色。

## 4. 查询与排序流程

### 4.1 查询图多视角

查询图片会生成 8 个模型视角：

- 0°、90°、180°、270° 四个方向；
- 每个方向同时生成中心裁剪和完整画面缩放。

这可以缓解手机横竖方向、鞋子位置及画面比例不一致的问题，但不能补回已经被裁掉或遮挡的鞋体。

### 4.2 两阶段检索

1. 使用全局向量比对全部样品。
2. 按编号开头的连续数字合并为鞋型族，例如 `280573 black` 和 `280573 l.blue` 属于 `280573`。
3. 选出全局最接近的 80 个鞋型族。
4. 对候选计算局部块相似度，核对结构细节。
5. 鞋型族排序使用全局分数和局部分数融合。
6. 在同一鞋型族内部，再使用视觉和颜色分数选择具体配色。
7. 最终展示 5 个不同鞋型族，避免同一鞋型的多个颜色占满 Top 5。

当前实现中的主要融合比例：

- 鞋型族排序：全局 20%，局部 80%；
- 同鞋型配色排序：全局视觉 70%，前景颜色 30%。

这些分数是相似度排序指标，不是统计意义上的正确概率。

## 5. 本地数据与版本迁移

- 数据保存在当前浏览器、当前站点域名对应的 IndexedDB 中。
- 不同手机、不同浏览器之间不会自动同步。
- 清理浏览器网站数据会删除本地鞋库。
- 更换设备或清理数据前，应先导出完整 JSON 备份。
- V5 特征与 V4 及更早版本不兼容；升级后需要清空旧样品并重新导入 Excel。

## 6. 当前验证结果与限制

使用 731 张样品和 11 张现场测试图进行浏览器实测：

- `280573 burgundy`、`280573 l.blue`、`280525 taupe` 和 `280669` 的主要测试图可排到第 1；
- 部分浅色鞋或高度相似的黑色鞋仍可能只进入前 2～3；
- 电脑浏览器单次查询约 2.3～2.5 秒，手机速度取决于设备性能。

当前主要限制：

- 旧样品库多数只有一张白底或双鞋图，与手机查询图的构图差异较大；
- 每个编号只有一张参考图时，无法覆盖旋转和不同视角；新规范用三张统一浅灰棚拍图改善这一点；
- 同一鞋型不同颜色的结构几乎完全相同；
- 白鞋与浅色地面、黑鞋与阴影容易降低前景分离质量；
- 通用视觉模型没有使用本项目的鞋款数据进行专门训练。

## 7. 如何进一步提高准确率

准确率还没有达到理论极限，但继续只调融合权重的收益已经有限，并可能让一部分测试图变好、另一部分变差。建议按以下顺序升级。

### 7.1 优先方案：同一编号增加多张样品图

这是当前成本最低、预期收益最高的方案，而且不需要增加服务器或更换模型。

推荐每个完整编号提供 3 张：

1. 单鞋外侧标准侧面图；
2. 双鞋组合图；
3. 单鞋前外侧 30°～45° 图。

如果查询经常从内侧拍摄，可增加第 4 张内侧图。

Excel 中推荐一个完整编号占一行，将三张图片分别嵌入 `图片1`、`图片2`、`图片3`。导入器会按图片所在的行和列拆成独立特征记录。同编号重复多行的旧模板仍保持兼容。不要把多张图拼接成一张图。

多参考图有效的原因：

- 系统可以从多个参考中选择与当前查询角度最接近的一张；
- 多个棚拍角度可以覆盖手机查询时常见的侧面和斜侧构图；
- 不同照片可以分别保留鞋头、鞋跟、鞋底和饰条细节；
- 同编号结果会自动合并，不会因为增加参考图而占用多个结果位。

建议先给容易混淆、实际查询频率高的 50～100 个编号补图，再用新的现场测试集比较提升，不必一开始重拍全部样品。

### 7.2 统一拍摄规范

按照[鞋库图片拍摄规范](./鞋库拍摄规范.md)执行，尤其要保证：

- 单鞋标准侧面；
- 鞋子占画面 70%～85%；
- 鞋头、鞋跟和鞋底完整；
- 背景简单且与鞋色有反差；
- 手不遮挡主要结构。

规范拍摄可以同时提高现有模型和未来专用模型的效果。

### 7.3 Excel 增加结构化鞋型与颜色字段

当前系统根据编号开头的数字推断鞋型族。更可靠的做法是在 Excel 中明确增加：

- `鞋型编号`，例如 `280573`；
- `颜色`，例如 `l.blue`；
- `完整样品编号`，例如 `280573 l.blue`。

这样可以消除编号书写差异，明确执行“先鞋型、后颜色”的排序。该方案需要同步修改 Excel 模板和导入代码。

### 7.4 增加鞋体检测或分割模型

在 DINOv2 前增加轻量鞋体检测/抠图模型，可更稳定地去掉手、地砖和空白区域，并自动把鞋体转正后再提取特征。

代价：

- 网页模型体积和首次加载时间增加；
- 手机内存和推理时间增加；
- 浅色鞋与浅色背景仍需要专门验证。

### 7.5 使用项目数据训练专用检索模型

长期准确率上限最高的方案，是用“样品图—现场实拍图—正确编号”训练鞋款度量学习模型。

训练需要电脑 GPU 或云端资源，但训练完成后仍可导出量化 ONNX 模型并部署到 GitHub Pages；最终使用阶段仍可保持纯前端和离线检索。

训练数据至少应包括：

- 每个重点鞋款的多张样品图；
- 不同手机、距离、角度、光线和背景的实拍图；
- 容易混淆的同鞋型不同配色负样本；
- 明确的正确编号标注。

### 7.6 业务兜底方案

如果业务要求接近 100% 确认，可将视觉检索定位为“快速缩小候选”，再结合：

- 鞋盒条码或二维码；
- 人工核对 Top 3；
- 鞋型编号和颜色筛选；
- 关键鞋款的多角度图册。

视觉匹配适合快速召回，但不应把相似度分数当作绝对身份认证。

## 8. 推荐迭代顺序

1. 固化拍摄规范并收集独立验收集。
2. 给高频和易混淆编号补充 3 张参考图。
3. 统计 Top 1、Top 3、Top 5 命中率，而不是只看个别图片。
4. 再决定是否增加结构化字段或鞋体检测模型。
5. 数据量足够后，评估训练专用检索模型。

这个顺序能够先用最低成本验证多参考图的实际收益，再决定是否承担更高的模型开发和手机性能成本。
